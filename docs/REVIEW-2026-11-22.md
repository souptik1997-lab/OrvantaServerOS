## Remaining risks and open items

- **Live password.** live-config sets the well-known password for the live
  user and passwordless sudo. Mitigated by the firewall and masked services,
  not removed. The installed system must never ship a shared password.
- **Masked services.** An administrator who wants Cockpit or Samba in the
  live session must `systemctl unmask` and enable them and open the firewall.
- **Docker and the firewall.** Docker manages its own nftables/iptables
  tables. The ORVANTA table does not flush them, but the interaction is
  untested; Docker is masked in the live image for now.
- **Reproducibility.** `SOURCE_DATE_EPOCH` is pinned to the commit time and
  the package list is published as `*.packages`, but packages come from the
  live Debian archive at build time, so two builds on different days differ.
  Bit-for-bit reproducibility is not claimed; use `snapshot.debian.org`
  mirrors to pin an archive state when that becomes a requirement.
- **Secure Boot / hardware.** Not tested. No claim is made.
- **Boot not tested.** Next step: boot the ISO in UEFI and BIOS mode (QEMU or
  a spare PC) and confirm KDE starts, `sudo nft list ruleset` shows the
  ORVANTA table and `sudo ss -tlnp` shows no Cockpit/Samba listeners.
- **ISO workflow trigger.** `build-iso.yml` runs on every push to a PR that
  touches build inputs (GitHub evaluates the whole PR diff) and on manual
  dispatch; concurrent runs on one branch are cancelled. Each run takes
  ~16 minutes.
- **Node.js 20 actions.** `actions/checkout@v4` and `upload-artifact@v4`
  trigger GitHub's Node.js 20 deprecation warning; update when v5 versions are adopted.
